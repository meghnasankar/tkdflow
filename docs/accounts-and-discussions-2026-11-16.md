## Prepared implementation

- Existing email sign-in, registration, recovery and private profiles now include the previously approved neutral age screen and 13–99 optional profile age. All child guidance remains private/public-learning only; no parent-managed child profile is represented as working.
- `supabase/community.sql` adds moderated topics, replies, reports, public usernames and an owner-assigned moderator list. Public reads contain no author UUID, full name, age, email or private profile fields. Writes are narrow server functions; status, author, username and timestamps cannot be supplied by the browser. New posts/replies are pending until approved. Server locks/rate limits bound repeated submissions.
- Adult permission comes from `private.account_eligibility`, never editable profile age or user metadata. Teens may read and privately report content but cannot publish. Unknown eligibility cannot publish. Moderators are assigned to verified auth user IDs by the project owner; the UI cannot self-promote.
- `supabase/enrollment.sql` and `supabase/functions/enroll/` prepare an email-first registration path. The endpoint validates self-declared age before contact collection, discards the exact age and issues a random 15-minute one-use ticket. The Auth Before User Created hook consumes its hash and records only teen/adult eligibility. Direct signups without an unexpired ticket are rejected. This is screening, not identity/age verification.
- The initial supported Google path is **create and confirm an account by email, then connect Google from the private profile for subsequent sign-in**. New Google-first registrations are rejected by the hook. The UI explains this. A Google-first enrollment broker is a separate future implementation, not advertised as working here.
- Nine real editorial discussion guides are public even while the service is unavailable. They are not fictional member posts, replies or activity. `supabase/discussion-guides.sql` seeds their stable IDs for real replies after connection.
